# Rubric: is this reproduction package ready to post?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| environment-recorded | The repro report's environment record (project version, platform, install method, build profile), read against the environment the issue states and the bug-report template line in repo facts | Principle: a stranger can tell what setup produced the result. Pass if the report names the version of the project it tested, and any difference from the issue's version or platform is called out. Platform, install method, or build profile are required only when the issue says the behavior depends on them. | required |
| steps-followable | The repro report's commands, inputs, and steps, read together with the issue's own steps | Principle: a stranger can re-run it from the report alone. Pass if the report gives the exact commands and inputs from a starting state to the trigger, or states that it ran the issue's steps exactly as written and those steps are complete. Fail if a step a stranger would need is missing or vague. | required |
| behavior-matches | The artifacts pasted in the repro report (output excerpts, logs, error text), read against the specific symptom the issue describes | Principle: the evidence shows the same failure the issue describes, not a neighbouring one. Pass if a pasted artifact shows the issue's specific symptom (the same error, panic, or wrong output), or, for a cannot-reproduce, shows the issue's steps producing correct behavior. Fail if the artifact shows a different error or symptom, or if there is no artifact. | required |
| claims-backed | Every statement in the claim comment and repro report about what was observed or what it means, read against the pasted artifacts and the report's own steps | Principle: a reader can check every claim about what happened. The main result (reproduced or not, and the behavior observed) must be backed by a pasted artifact. Any other claim passes if it is specific enough that a stranger could check it by re-running the report's own steps with a stated change. Fail if the main result has no artifact, if a claim is sweeping or uncheckable ("on all my machines", "everyone I know"), or if an interpretation is stronger than its artifact ("exactly the class of failure" beside a different error). An evidenced cannot-reproduce passes. | required |
| follows-policy | The contribution policy line in repo facts (including any AI-use disclosure requirement), read against the claim comment and repro report | Principle: the words follow the repo's stated rules, and work in this course is AI-assisted. A requirement applies only where the policy says it applies: one aimed only at pull requests or code does not apply to these comments. A requirement to state something that does apply to comments or to all contributions (for example, disclose AI use, the tool, or its extent) passes only if that statement appears in the claim comment or repro report; its absence is a fail, not evidence that no AI was used. A requirement about how the text was produced (for example, "written by a human in their own words") passes unless something in the comments contradicts it. A policy with no requirement on comments passes. | required |
| claim-specific | The claim comment, read against the issue context | Principle: the claim speaks to this issue, not to issues in general. Pass if the claim comment names this issue's specific behavior and the next concrete step its author will take. Fail if it is a "+1", a "same here", or boilerplate that could be posted on any issue. | required |

## Verdict rule

Accept if every required check passes. Reject if any required check fails. Unclear counts as fail. Preferred checks never change the verdict.

## Notes on heuristics

- **environment-recorded:** "required only when the issue says the behavior depends on them" is a judgment line, not a measured one. It exists so a report is not held for skipping a field that cannot change this bug.
- **follows-policy:** "work in this course is AI-assisted" is a fact about this course's workflow, not something a bundle states. It is why a missing disclosure counts as a fail rather than as "no AI was used". Sorting a requirement into "state something" versus "how it was produced" is a judgment call when a policy mixes both.
- **claims-backed:** the line between "specific enough to check by re-running" and "sweeping" is a judgment call. The test: could a stranger holding only this report run something and see whether the claim is true? Whether an interpretation goes beyond its artifact is also a judgment call; the test is whether a reader holding only the pasted artifacts would reach the same conclusion.
