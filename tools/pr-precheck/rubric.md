## Verdict rule

Accept if every required check passes. Reject if any required check fails. Unclear counts as fail. Preferred checks never change the verdict.

## Notes on heuristics

- **Honest shortfalls:** a PR that does less than everything can still be ready. Each check's pass condition says what a disclosed shortfall does there (for `tests-shown`, clauses E1–E2); the fail is for the silent version.
- **diff-within-plan:** whether a hunk is "inside the plan's scope" is a judgment call when the plan names an area rather than exact lines. The test is whether the plan's author would recognise the hunk as part of the planned change.
- **tests-shown:** which step is the "main reproduction" (P1) is a judgment call when a plan names several; it is the one that reproduces the issue's reported failure. A "before" may come from the plan's repro evidence instead of being re-run.
- **meets-repo-asks:** whether a contributing ask "applies to this change" (P2) is a judgment call; for example, a changelog ask may not apply to a test-only change.
